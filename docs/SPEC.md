# Open CGenFF-compatible parameter assignment: technical specification

Status: draft 1 (2026-10-29). Owner: Carlos Baiz. Evidence behind every number here: `docs/FINDINGS.md`.
Paper abbreviations (full citations in `docs/REFERENCES.md`):
**P-I** = Vanommeslaeghe & MacKerell, JCIM 2012 (perception, typing) ·
**P-II** = Vanommeslaeghe, Raman & MacKerell, JCIM 2012 (parameters, charges) ·
**P-v5** = Croitoru et al., JCTC 2025 (CGenFF 5.0) · **P-X** = Soteras Gutiérrez et al., BMC 2016 (halogen lone pairs) ·
**P-Orr** = Orr et al., JCIM 2022 (fidelity of third-party tools).

---

## 1. Goal, scope, definition of done

**Goal.** An open-source program that, given a small organic molecule with explicit hydrogens and bond orders,
reproduces the output of the CGenFF program **version 5.0** (SilcsBio / MacKerell lab) as closely as possible:

1. CGenFF atom types (incl. formal charges assigned by typing rules, improper-dihedral flags, warnings/errors),
2. partial atomic charges and per-atom charge penalties,
3. bonded parameters missing from CGenFF, assigned by analogy, with their source parameter and penalty,
4. halogen lone-pair sites,
5. a CHARMM toppar stream file (`.str`) equivalent to the official output; later GROMACS/OpenMM exports.

**Non-goals.** New parameter optimization (QM fitting), changing CGenFF parameters, distributing CGenFF force-field
files, reproducing program versions other than 5.0 (older versions only as secondary benchmarks).

**Definition of done (v1.0)**, measured on the sealed external set B5 (section 7):
- atom types: ≥ 95 % of molecules fully identical (all atoms), ≥ 99.5 % of atoms;
- charges: identical to 0.001 e for every molecule whose types match and whose parameters need no analogy;
  max |Δq| ≤ 0.02 e for ≥ 90 % of the remaining type-matched molecules;
- bonded parameters by analogy: same source parameter for ≥ 90 % of analog parameters; penalty within ±10 % for ≥ 90 %;
- `.str` output loads in CHARMM/OpenMM without manual edits.
These targets are provisional until B5 exists; revisit after M7.

## 2. Ground rules (apply to every contributor, human or agent)

### 2.1 Clean room
- Build only from the published papers/SI and the public data in section 6. Do **not** download, decompile,
  disassemble, or inspect the CGenFF program, its rule files, or any SilcsBio binaries/data.
  (Note: `data/cgenff5/developer_program/*.exe` are SilcsBio training executables: do not run or inspect them.)
- Official CGenFF outputs may be used **only as test oracles**, and only if the license under which they were obtained
  allows it (open decision D4, section 11).

### 2.2 Naming
- Do not call the tool "CGenFF" (P-Orr asks that the name be reserved for the official program + current parameters).
  Use "CGenFF-compatible". The repository's working name `open-cgenff` is a placeholder (decision D1).
- Every output file states: tool name + version, the CGenFF parameter version it targets (5.0), and that it is not
  the official CGenFF program.

### 2.3 Data handling
- CGenFF/CHARMM force-field files have no explicit license: never commit them. `scripts/fetch_data.sh` fetches them at
  pinned commits into `data/` (git-ignored). Code must read them from there at runtime.
- Papers/SI PDFs are copyrighted: never commit them (they live outside the repo; see `docs/REFERENCES.md`).
- Small factual extracts needed for tests (e.g. `tests/fixtures/si_v5_reference.json`) are allowed, with citation.

### 2.4 Benchmark hygiene
- Test splits are sealed: look only at aggregate metrics, never at per-molecule failures (section 7.2).
- Never edit reference data to make a test pass. Data errors go in `benchmarks/*/NOTES.md` with evidence.

## 3. Inputs and outputs

**Input:** mol2 (primary; same as the official program), SDF/MOL, or SMILES via RDKit. Requirements (as for the official
program, P-I): all hydrogens present, correct protonation/tautomer, correct bond orders. "Aromatic" bonds in the input
are allowed and resolved by the resonance algorithm (5.3). Optional mode: ignore input bond orders and assign from
connectivity (P-I offers this; not recommended).

**Output:** CHARMM stream file in the official layout (P-II SI Tables S2–S4, P-v5 SI Table S10):
```
* Toppar stream file generated by <tool> <version> (CGenFF-compatible; not the official CGenFF program)
* For use with CGenFF version 5.0
read rtf card append
36 1
RESI <name>  <net charge> ! param penalty= <max over assigned params> ; charge penalty= <max over atoms>
GROUP            ! CHARGE   CH_PENALTY
ATOM <name> <type> <charge> !  <charge penalty>
BOND ...            (all bonds)
IMPR ...            (from 'impr' typing actions)
LONEPAIR COLINEAR <lp> <X> <C> DIST <d> SCAL 0.00   (aromatic Cl/Br/I; 5.12)
END
read param card flex append
BONDS / ANGLES / DIHEDRALS / IMPROPERS
<types> <params> ! <RESI>, from <source types>, penalty= <tps>     (only parameters absent from CGenFF 5.0)
END
RETURN
```
Plus a machine-readable JSON report (types, charges, penalties, parameter provenance, warnings) for benchmarking.

```

  perception/  rings.py (5.2), resonance.py (5.3), aromaticity.py (5.4)
  typing/      engine.py (P-I rule language interpreter, 5.5); rules/cgenff_v5.rules (5.6)
  params/      database.py (5.8), penalties.py + rules/penalties_v5.rules (5.9-5.10), analogy.py
  charges/     increments.py, penalties.py (5.11)
  lonepairs.py (5.12)
  cli.py
  benchmarks/  B0/B1/B3 builders, scoring, runner producing JSON/markdown reports (section 7);
               `python -m open_cgenff.benchmarks --check-floors`
```

Pipeline: read → perceive (rings → resonance → ring classes) → type (+ formal charges, impropers, warnings)
→ look up / assign-by-analogy bonded parameters → charges (+ analog increments, penalties) → lone pairs → write.

## 5. Component specifications

Each item lists: what the sources say, status, and acceptance tests.

### 5.1 Input and bond orders
Parse mol2 (Tripos) including `ar` bonds and formal charges in atom types (e.g. `N.4`). Keep input atom order: the
official resonance and `altnum` behaviour can depend on it (5.3, 5.5).
Accept: round-trip all molecules of B1/B2/B3 and the 126 P-I SI special cases without loss of graph or charge.

### 5.2 Ring perception (P-I)
- Rings are only those with < 8 atoms. Larger rings are treated as acyclic.
- Each non-bridgehead atom needs its smallest ring; each bridgehead atom needs its three smallest rings.
  (SSSR is explicitly unsuitable.) P-I's implementation: homeomorphically reduced graph (Balaban variant) + non-SSSR
  Figueras breadth-first message passing with messages dropped after 4 bonds. Any algorithm producing the same ring
  sets is acceptable.
- 3- and 4-membered rings are typed immediately; 5–7-membered rings go to aromaticity perception.
- Ring conditions in rules consume a ring once matched (5.5).
- Open point: precise definition of "bridgehead" for this purpose (pilot used ≥ 3 ring bonds). Calibrate on B1/B2.
Accept: unit tests on naphthalene, norbornane, bicyclo[2.2.2]octane, spiro[4.4]nonane, cubane-like cages, the P-I SI
special cases (`specialcases/*.mol2` from the P-I SI archive: 5rings1/2, bigdiamond, spiro1, fullerenes → warning).

### 5.3 Resonance resolution (P-I)
- Operates on the subgraph of "aromatic" input bonds. Depth-first traversal with a trail; choices: bond order of
  ambiguous edges; formal charge of N (0 or +1, neutral tried first); terminal O (0 or −1). Valence violation →
  destructive backtracking; branch completion → constructive backtracking; each complete structure is scored and kept
  only if its score is strictly lower; exit early at score 0.
- Score: `8|Z_mol| + 4 Σ_{Z<0}|Z_atom| + 3 Σ_{Z>0}|Z_atom| + 2 (N_potential_aromatic − N_aromatic)`
  (coefficients changed from 4,2,2,1 in program 0.9.7). Potential aromatic ring = 5–7-membered ring whose atoms all have
  ≤ 3 substituents.
- Worked examples in P-I: pyridinium → two structures, score 6 each; Fig. 4 molecule → structures scored 12 and 11.
- Ties are broken by traversal order (first structure found wins) ⇒ output can depend on input atom order. The pilot
  used an RDKit enumeration + heuristic tie-break and got 1 avoidable error class (quinolinium). Implement P-I's
  algorithm literally, starting from the lowest-index atom, and calibrate start/choice order against B5.
- The resonance formal charges are separate from the formal charges assigned by typing rules (5.7).
Accept: P-I worked examples reproduce the published scores; pilot regression on B1 not worse.

### 5.4 Ring classes and aromaticity (P-I)
Four classes: all-sp3 (no ring atom in any double bond); all-sp2 (every ring atom in a double bond, except at most one
N/O/P/S with only single bonds); aromatic; mixed (everything else). Aromatic: 5–7-membered, all atoms ≤ 3 substituents,
exactly 6 in-ring π electrons, counting: in-ring double/triple bond = 2; atom with an exocyclic double bond that belongs
to another aromatic ring = 1; heteroatom with only single bonds not in another aromatic ring = 2; such a heteroatom in
another aromatic ring = 1 or 2, whichever makes the ring aromatic. Iterate over all candidate rings until no ring changes.
P-I: this reproduces aromatic vs non-aromatic types on all 315 cyclic model compounds.
Known limitation (by design): [4N+10]annulenes fail; only two `altnum` symbols.
Status: implemented in `prototype/perceive.py` (on RDKit Kekulé forms).

### 5.5 Typing rule engine (P-I, fully specified)
Rule file = categories `cat <name> … end`. Each rule: `<action> : <conditions…> [optional actions…]`.
Action `typ <TYPE>` assigns the type; `sub <CAT>` jumps to a category. Typing of each atom starts at `cat main`;
in each category the **first** rule whose conditions all hold fires (rule order matters; specific rules first).
Conditions (P-I Table 1):

| keyword | meaning |
|---|---|
| `el <X>` | element X |
| `elha` / `elos` | any halogen / O or S |
| `nb <n>` | valence = number of electrons in bonds (sum of bond orders, H included) |
| `rings <n>` | atom is in n rings |
| `ring3 <s>` / `ring2 <s>` / `arom <s>` / `ring23 <s>` / `ring <s>` | member of an all-sp3 / all-sp2 / aromatic / mixed / any ring of size s; a matched ring is consumed (`arom 6 arom 6` = fusion atom of two aromatic 6-rings) |
| `self` | the parent atom (detect ring closures inside nested `ne`) |
| `ne (c…) (c…) …` | neighbours: first condition group matches some neighbour, which is then "used"; next group matches an unused neighbour, etc. Greedy, in order, no backtracking (P-I: by design, avoids subgraph isomorphism). Nestable. |
| `bo <n>` | order of the last bond traversed by the enclosing `ne` |
| `inring` | last bond traversed by `ne` is in a ring |
| `! (c…)` | not |
| `or (c…) (c…) …` | or |

Optional actions: `charge <n>` (formal charge used by charge assignment), `impr` (generate improper dihedral),
`warn "<msg>"`, `err "<msg>"` (fatal), `altnum` (replace `?` in the type by 1/2 so that in a conjugated chain
double-bonded atoms share a symbol and single-bonded neighbours alternate; the 1↔2 choice is arbitrary and
parameter-symmetric).
Status: not implemented (pilot used Python rules). Decision: implement this language exactly (it is published, fully
specified, and matches CGenFF's ad-hoc type design); express all rules in it.
Accept: one unit test per keyword incl. greedy `ne` order dependence; the Appendix A rules parse and fire as in
P-I case studies (pyridinium N → NG2R61 with charge +1; 1,3-pentadiene C1 → CG2DC3, C2/C3/C4 → CG2DC? with altnum).

### 5.6 Typing rules (content: must be reconstructed)
The official rule file is unpublished. Sources: Appendix A (all rules printed in P-I Fig. 5 and P-v5), the MASS-line
type descriptions in `top_all36_cgenff.rtf`, the pilot rules (`prototype/typer_pilot.py`, which encode ~110 decisions
learned from B1-train), and the reference molecules (B1, B2). Notable conventions found so far are listed in
`docs/FINDINGS.md` §3.3. Work type-family by type-family; keep rules ordered most-specific-first; log every change
(section 10).
Accept: section 7 targets.

### 5.7 Formal charges (typing-rule charges)
Charge assignment needs integer formal charges q0 placed by typing rules, placed so delocalized groups stay symmetric:
carboxylate −1 on the carbon (CG2O3), amidinium/guanidinium +1 on the carbon (CG2N1/CG2N2 and `sub CG2D: ne (bo 2 el N nb 4) charge 1`),
ammonium N +1 (`sub NG_3P: nb 4 charge 1`), pyridinium-type ring N +1 (`typ NG2R61: arom 6 ne (bo 1) (bo 1) charge 1`).
Inferred from training data (FINDINGS §2.2): PG1 −1, PG2 −2, OG312 −1, SG302 −1, SG3O1 −1, CG2R53 +1 in imidazolium.
P-v5 mentions undocumented "specific rules … resetting the formal charges" to fix resonance mismatches between training
and prediction: expect a few special cases.
Accept: for every B1/B2 molecule whose increments are complete, q0 from the rules equals round(q_ref − q_increments).

### 5.8 Parameter database
Read `par_all36_cgenff.prm` (v5.0, aligned) for parameter values and `par_all36_cgenff_increments.prm` for charge
increments. (Same bonds/angles/impropers; dihedral lines differ only in alignment/order.) Canonical ordering rules are
documented in the file header: element priority C < N < O < P < S < halogens (by Z) < misc (by Z) < H, alphabetical
within element; bonds lowest priority first; angles swap 1↔3 if 3 < 1; dihedrals reversed if 3 < 2 (if 2 = 3, compare
4 vs 1); impropers unsorted. The analogy search iterates parameters in this collated order (P-II), so tie-breaking
between equal-TPS candidates depends on it.

### 5.9 Bonded parameters by analogy (P-II, algorithm fully specified)
- For each missing parameter, scan all existing parameters of that kind; total penalty score (TPS) = Σ per-position
  substitution penalties + bond-group penalties. Also evaluate the reversed missing parameter; use the lower. Return the
  lowest-TPS parameter (first found on ties, in collated order). Cache results.
- Matrices: **bonded** matrix for inner positions (both atoms of a bond, centre of an angle, atoms 2–3 of a dihedral,
  all four atoms of an improper); **nonbonded** matrix for outer positions (angle ends, dihedral ends).
  Inner-position penalties ×10 (for impropers ×10 only for the central atom). The matrices are not symmetric.
- Bond groups (program ≥ 0.9.6): `bgrp <penalty> <types…>`. Bond/angle/dihedral contain 1/2/3 virtual bonds; a virtual
  bond belongs to a group if both atom types are in it. For each virtual-bond position, if membership differs between the
  missing and the candidate parameter, add that group's penalty; ×10 for the central bond of a dihedral and for any bond
  of an angle or bond parameter. The first two groups count as equivalent. v0.9.6 groups: Appendix B.
- Penalty interpretation printed in outputs: < 10 fair; 10–50 basic validation; > 50 extensive validation.
Status: not implemented. Matrix values unknown → 5.10.

### 5.10 Penalty matrix (content: must be reconstructed)
Generated by a hierarchical "parameter assignment" section of the rule file: categories with entries `typ`/`sub`, each
`: pri <p> alt <entry> <penalty> … up <offset>`. Substitution cost = within-category `alt` value; otherwise climb with
`up`, use the parent's `alt` to the sibling subcategory, descend choosing the lowest `pri` (worked example: NG3P3→NG321 =
8 + 2 + 0 = 10; NG3P3→NG311 = 10.5). Largest category: 25 H types, machine-generated from reference bond lengths; next:
10 sp3 O types. Published: only the NG3 extract (Appendix B, = bonded matrix, verified) and v0.9.6 bond groups.
Reconstruction plan:
1. Seed the tree from type families (CG3*, CG2R5*, CG2R6*, NG3*, OG3*, HG* …), MASS descriptions and Appendix B.
2. Fit `pri/alt/up` (half-integer grid) to the annotated parameters in `par_all36_cgenff*.prm`: comments
   `from <source>, penalty= <tps>` record official analogy choices (7,234 distinct; 5,089 differ at one position, which
   directly gives one matrix element; FINDINGS §4). Treat as noisy: annotations span program versions.
3. Validate leave-one-out: remove the annotated parameter from the database, rerun the search, compare chosen source and TPS.
4. Fit the H category from bond lengths as P-II describes.
Accept: see M5.

### 5.11 Charges and charge penalties (P-II; verified exactly)
- `q_i = q0_i − Σ_j β_ij`, extended: each bond parameter carries one increment, each angle two, each dihedral three.
  For an instance A-B(-C(-D)) matching the parameter-file orientation, increment k transfers charge along bond k
  (q_first −= d, q_second += d). If the instance matches in reverse order, reverse the atoms.
- Increments for missing parameters come from an analog parameter found with the nonbonded matrix at **all** positions
  (P-II) — may differ from the bonded-parameter analog. Dihedral increments whose analogy penalty exceeds 50 are ignored
  (increment 0, penalty 50). Both rules are from 2012: confirm on B5.
- `N/A` increments (P-v5 file) contribute nothing.
- Per-atom penalty (P-II eq 4): `σ_i = sqrt( Σ_n cbrt(|β_n| + δ) σ_n² )`, δ = 0.05⁶, where β_n is the **net** charge one
  parameter instance moves onto atom i and σ_n that parameter's penalty. RESI header: charge penalty = max σ_i;
  param penalty = max over assigned parameters.
- Training (only needed to extend CGenFF; increments are published): three-stage restrained least squares
  (bonds → angles → dihedrals; restraint k = 10⁻³ in 2012; P-v5 scanned 42 values from 10⁻⁴ to 5×10⁻¹⁷ and kept the
  model best correlated with the previous version), rounding to 0.001 e, constraints of P-II Table S1.
Status: `prototype/charges.py` reproduces program 5.0 output exactly (charges and penalties) on all three SI molecules.

### 5.12 Halogen lone pairs (P-X)
Aromatic Cl/Br/I get a massless, LJ-free virtual site, colinear with C–X, at 1.64 / 1.89 / 2.20 Å from X, charge +0.05 e
(fixed). RTF syntax: `LONEPAIR COLINEAR LP X C DIST d SCAL 0.00`. How the program offsets the halogen charge is not
published: the best simple rule (halogen = increment charge − 0.05) reproduces training charges within 0.04 e
(mean 0.017 e). Some RTF entries have DIST 0.0: investigate. NBFIX halogen–amide-O terms come with the parameter file.
Calibrate on B5.

### 5.13 Other terms
Urey–Bradley and NBFIX come with the parameter file. Improper dihedrals: generated where typing rules carry `impr`;
improper atom order as in the official output (central atom first; see fixtures). LJ parameters: by atom type.

### 5.14 Writers
CHARMM `.str` (section 3). GROMACS and OpenMM: reuse established converters (e.g. ParmEd; the Lemkul lab
`cgenff_charmm2gmx` script) rather than writing new ones. Accept: OpenMM can build a system from the output for all
B3 molecules; energies match CHARMM where CHARMM is available.

### 7.2 Hygiene
- Rule writing may look at failures in B1-train, B2-train, B5-dev only.

### 7.3 Metrics (benchmark runner must report all, JSON + markdown)
- typing: fraction of molecules with all atoms correct; atom accuracy; per-type precision/recall; confusion pairs
  (dev splits only). `altnum` equivalence: CG2DC1≡CG2DC2, CG2D1O≡CG2D2O, CG25C1≡CG25C2, CG251O≡CG252O.
- charges: max and RMS |Δq| per molecule; fraction exact at 0.001 e; split by "all increments exact" vs "analogy needed".
- penalties: |Δσ| per atom; RESI header penalties.
- analogy: same source parameter (%); |ΔTPS|; parameter value agreement.
- runtime: molecules/s (official program: ~30/s on one 2012 core, P-II).

### 7.4 Regression floors (current pilot; CI must enforce, production must beat)
B0 exact; B1-train ≥ 874/904 (96.68 %, printed 96.7 %), B1-test ≥ 212/226 (93.81 %) molecules fully correct;
B3 100 % (34/34). Enforced as exact counts in `src/open_cgenff/benchmarks/floors.py` and by CI
(`.github/workflows/ci.yml`).

## 9. Known unknowns and risks
1. Typing rule file unpublished (5.6): largest effort; the last few % are per-chemistry quirks learnable only from data.
2. Penalty matrix mostly unpublished (5.10); annotations are mixed-version → imperfect fidelity for analog parameters.
3. Order dependence: resonance ties and `altnum` depend on input atom order (5.3, 5.5).
4. Undocumented v5.0 formal-charge "reset" rules (5.7); halogen-charge offset (5.12); charge-increment analogy rules
   (5.11) unconfirmed for v5.0.
5. B1/B2 are training molecules: they bound performance from above; only B5 measures generalization.
6. Upstream updates (CGenFF 5.x): keep data pinned; treat upgrades as explicit migrations.
7. Legal/naming: see 2.1–2.2 and D1–D4.

## 10. Working conventions
- Python ≥ 3.10, RDKit, pytest; no network access in tests (data must be fetched beforehand); full benchmark < 2 min.
- Never hand-edit force-field values or increments; read them from `data/`.
- Every typing/penalty rule change: run B0/B1/B2/B3; no regression on dev splits beyond ±1 molecule without a
  written justification; append to `docs/RULES_CHANGELOG.md` (rule, motivating molecules, metric delta).
- Keep `prototype/` untouched as the reference baseline (bug fixes only).
